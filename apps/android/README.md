# Polaris for Android (`@polaris/android`)

The Polaris app as an Android app: a **Trusted Web Activity** (TWA) around the
hosted customer app ([`apps/app`](../app/README.md)). The app, package
`app.polarispay.twa` and named **Polaris**, opens `https://app.polarispay.app`
in Chrome, full screen and with no address bar, in the app's own dark colours.
It has the lime star as its launcher icon, and two shortcuts on a long press,
**Send** and **Receive**. It is generated with
[Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) 1.25.0 from
[`twa-manifest.json`](twa-manifest.json).

It exists for Agora's bounty, which asks for a mobile app (plan §3.1 and §6,
item 20). The installable PWA is the same app. This one installs from an APK
(and later from Google Play).

## Why a Trusted Web Activity

**Face ID has to keep working.** A Polaris account is a Mera passkey with the
PRF extension (rpId `polarispay.app`), and the key is derived from it in the
browser.

- **A TWA *is* the browser.** The page runs in the user's Chrome (or another
  browser that hosts TWAs), at its real origin, `https://app.polarispay.app`.
  So WebAuthn, Google Password Manager's passkeys and PRF behave exactly as
  they do in a Chrome tab.
- **One account everywhere.** The same passkey opens the same account in
  Chrome, in the installed PWA and in this app.
- **Nothing to add for passkeys.** A native app calling Credential Manager
  would need a `get_login_creds` statement on `polarispay.app`. A TWA doesn't.
- **No WebView, ever.** In a WebView, passkeys work only if the app wires
  them up itself, and PRF there is unproven. So when no browser can host a
  TWA, the app falls back to a Custom Tab (`fallbackType: customtabs`), which
  is the browser itself.
- **Android 9 or later** (`minSdkVersion 28`): the floor Mera's docs give for
  passkeys with PRF on Android, so the app won't install where Face ID
  couldn't work.
- **Privy works as on the web.** The app runs the hosted **web** bundle, so
  *Continue with email* uses the web Privy client, and Privy sees the web
  origin. The Privy **Android** app client
  (`NEXT_PUBLIC_PRIVY_ANDROID_CLIENT_ID`) is locked to a native package, so
  it belongs to a native build, if one is ever made. This app doesn't use it.

Chrome shows the page full screen only once the site vouches for the app
([Digital Asset Links](#digital-asset-links-and-the-fingerprint)). Until then,
the same app opens with a thin address bar at the top.

## Build it

One command, from the repository root:

```bash
pnpm --filter @polaris/android build              # a signed APK in apps/android/dist/
pnpm --filter @polaris/android build -- --bundle  # also a signed .aab, for Google Play
```

It needs Node 22, a **JDK 17 or later** and an **Android SDK with build-tools
34 or later**. It finds them itself, in this order, and downloads neither:

| | Looked for in |
|---|---|
| JDK | `POLARIS_ANDROID_JDK`, `JAVA_HOME`, Bubblewrap's (`~/.bubblewrap/config.json`, `~/.bubblewrap/jdk`), then Android Studio's bundled one |
| Android SDK | `POLARIS_ANDROID_SDK`, `ANDROID_HOME`, `ANDROID_SDK_ROOT`, Bubblewrap's (`~/.bubblewrap`), then Android Studio's default (`%LOCALAPPDATA%\Android\Sdk`, `~/Library/Android/sdk`, `~/Android/Sdk`) |

Android Studio has both. On a machine with neither, run
`npx @bubblewrap/cli@1.25.0 doctor`. Bubblewrap downloads Temurin 17 (from
Adoptium) and Google's Android command-line tools into `~/.bubblewrap`, where
the build finds them. You accept the Android SDK licence there.

Put machine-specific paths in `apps/android/.env`, which is git-ignored.
[`.env.example`](.env.example) lists every setting. Write Windows paths with
forward slashes (`F:/tools/jdk-17`).

What `build` does:

1. **Regenerates the project if needed:** when `twa-manifest.json` changed
   since the last generation (`manifest-checksum.txt`), or
   `POLARIS_ANDROID_APP_URL` names another URL.
2. **Finds the toolchain** and prints what it found.
3. **Signs** with the configured key, or with the local debug key, which it
   makes on the first build ([Signing](#signing)).
4. **Runs `gradlew assembleRelease`** (with `--bundle`, also `bundleRelease`).
   This uses Gradle 8.11.1 and the Android Gradle Plugin 8.9.1, from
   Bubblewrap's template, with `androidbrowserhelper` 2.6.2. The first build
   downloads them from services.gradle.org, Google's Maven and Maven Central
   into `.toolchain/gradle` (git-ignored), unless `GRADLE_USER_HOME` is set.
5. **Aligns and signs:** `zipalign`, then `apksigner sign`, then
   `apksigner verify --print-certs`. It checks that the signer is the key it
   meant to use. The `.aab` is signed with `jarsigner`.
6. **Reads the APK back** with `aapt2` and prints its package, its launcher
   activity and the URL it opens.
7. **Writes `dist/`** (git-ignored): `polaris-<version>-<debug|release>.apk`
   (and `.aab`), plus `build.json` with each file's size and SHA-256, the
   signing certificate's fingerprint and the aapt2 summary.

These are the steps `bubblewrap build` runs. They run here instead for three
reasons:

- It works with a standard Android Studio SDK. Bubblewrap wants a `tools/` or
  `bin/` folder at the SDK's root.
- Passwords go to `apksigner`, `jarsigner` and `keytool` through the
  environment. `bubblewrap build` puts them on the command line.
- It never stops to ask a question.

The generated project is a normal Gradle project, so Android Studio opens
`apps/android` as it is.

### Commands

| `pnpm --filter @polaris/android …` | What it does |
|---|---|
| `build` (`-- --bundle`) | The signed APK (and AAB), above |
| `generate` | Regenerates the Android project from `twa-manifest.json` with `npx @bubblewrap/cli@1.25.0 update`, non-interactively. Bubblewrap downloads the icons named in the manifest. They are the hosted app's `/icons/`, so while it runs this serves the same files from `packages/brand` on `127.0.0.1:3920` (`POLARIS_ANDROID_ICON_PORT`). That way the project can be generated before the site is up, always from the repository's own artwork |
| `fingerprint` | The SHA-256 fingerprint of the signing key's certificate, and the line to set on the app's server |
| `inspect` (`-- <apk>`, `-- --out <dir>`) | What Android reads from an APK (aapt2): the package, versions, launcher activity, `DEFAULT_URL`, the verified link host, the asset statement. It reads the last build's APK by default. `--out` also writes aapt2's raw dumps |
| `test` | 51 tests: the manifest's decisions (package, colours from the app's tokens, the shortcuts, the icons from `@polaris/brand`, Custom Tabs fallback, Android 9+), a generated project in step with the manifest, toolchain discovery, signing, the aapt2 parsers, and that no key, password or build is ever tracked |

## Install it on a phone

1. On the phone: **Settings → About phone**, tap *Build number* seven times.
   Then turn on **Developer options → USB debugging**.
2. Connect it and check it's there: `adb devices`. `adb` is in the SDK's
   `platform-tools`.
3. Install the build:

   ```bash
   adb install -r apps/android/dist/polaris-1.0.0-debug.apk
   ```

   Or copy the APK to the phone and open it, and allow the file manager to
   install unknown apps.
4. Open **Polaris**. It needs a browser that hosts Trusted Web Activities,
   which Chrome, installed on almost every Android phone, does. Without one,
   it opens as a Custom Tab in the default browser.

An APK signed with one key can't be installed over one signed with another.
`adb uninstall app.polarispay.twa` removes the old one first.

## Point it at the hosted app

The app opens `https://app.polarispay.app/` (the default). For any other
deployment, set `POLARIS_ANDROID_APP_URL` in `.env` or the shell, and build:

```bash
POLARIS_ANDROID_APP_URL=https://staging.polarispay.app/ pnpm --filter @polaris/android build
```

That rewrites `twa-manifest.json`, including the host, the start URL and the
icon URLs, and regenerates the project. Commit the diff if it's the new
default, or go back with
`git checkout -- apps/android/twa-manifest.json apps/android/manifest-checksum.txt apps/android/app`. The URL must be https with
no port, because a TWA only opens https and Android matches the bare host. The
site at that URL must also serve `/.well-known/assetlinks.json` (next
section).

Before `app.polarispay.app` is hosted, the app has nothing to show. To try it,
point it at a deployment that is up.

## Digital Asset Links and the fingerprint

Android checks the app and the site both ways before Chrome shows the site
full screen:

- **The app names the site.** The generated
  `app/src/main/res/values/strings.xml` has an `assetStatements` entry for
  `https://app.polarispay.app`, which the manifest declares as
  `asset_statements`.
- **The site names the app.**
  `https://app.polarispay.app/.well-known/assetlinks.json` must list the
  package and the **SHA-256 fingerprint of the certificate the APK is signed
  with**. `apps/app` serves it from two server-side settings
  ([`src/app/.well-known/assetlinks.json/route.ts`](../app/src/app/.well-known/assetlinks.json/route.ts),
  tested in `apps/app/test/assetlinks.test.ts`):

  | Variable | Value |
  |---|---|
  | `POLARIS_ANDROID_SHA256_FINGERPRINTS` | Every fingerprint the app may be signed with, comma-separated: `14:6D:E9:…` |
  | `POLARIS_ANDROID_PACKAGE` | `app.polarispay.twa` (the default) |

  Until a fingerprint is set, the route answers 404, and the app opens with
  the address bar.

**Getting the fingerprint.** There is a different one per key:

- **The key this machine signs with:** `pnpm --filter @polaris/android
  fingerprint`, which reads the keystore with `keytool -list -v`. The build
  prints it too, and records it in `dist/build.json`.
- **Any APK:** `apksigner verify --print-certs <apk>` prints the
  "certificate SHA-256 digest". The build turns it into the colon form.
- **Any keystore:** `keytool -list -v -keystore <file> -alias <alias>`, the
  `SHA256:` line.
- **On Google Play:** Play re-signs the app with its own key. In Play Console,
  open *Test and release → App integrity → App signing*, copy the **app
  signing key certificate**'s SHA-256, and add it beside the upload key's.

**Checking it:**

```bash
curl https://app.polarispay.app/.well-known/assetlinks.json
# Google's own reader of the statement list:
curl "https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://app.polarispay.app&relation=delegate_permission/common.handle_all_urls"
# On the phone (Android 12+): the verification state, and a fresh check
adb shell pm get-app-links app.polarispay.twa
adb shell pm verify-app-links --re-verify app.polarispay.twa
```

**Before the site is up, or on a debug build:** Chrome can skip the check for
one origin. Turn on `chrome://flags/#enable-command-line-on-non-rooted-devices`,
then run this and restart Chrome:

```bash
adb shell "echo '_ --disable-digital-asset-link-verification-for-url=\"https://app.polarispay.app\"' > /data/local/tmp/chrome-command-line"
```

Verification also makes the phone open `https://app.polarispay.app/…` links
in the app, including pay and claim links from WhatsApp. The intent filter
has `autoVerify`.

## Signing

- **Without configuration**, the first build makes a local debug key,
  `.keys/polaris-debug.keystore` (PKCS12, RSA 2048, alias `polaris-debug`).
  Its random password goes in `.keys/polaris-debug.env`. Both are
  git-ignored, and nothing prints the password. Delete both to start over;
  the fingerprint changes.
- **An upload or release key:** set `POLARIS_ANDROID_KEYSTORE` (the path),
  `POLARIS_ANDROID_KEY_ALIAS`, `POLARIS_ANDROID_KEYSTORE_PASSWORD` and,
  if different, `POLARIS_ANDROID_KEY_PASSWORD`, in `.env` or the shell. The
  output is then named `…-release.apk`.
- **Never commit a keystore or its passwords.** `.keys/`, `*.keystore`,
  `*.jks`, `.env`, `dist/` and `.toolchain/` are ignored, and a test fails
  if any of them is ever tracked.

## Publishing later

1. **A Google Play Console developer account** for the team (a one-time fee
   and an identity check; only the team can do this).
2. **An upload key**, kept outside the repository (`keytool -genkeypair …`),
   configured as above. Then `pnpm --filter @polaris/android build --
   --bundle`.
3. **In Play Console:** create the app with package `app.polarispay.twa`.
   The package is permanent once published. Opt in to Play App Signing and
   upload `dist/polaris-<version>-release.aab`. Fill in the store listing
   (`store_icon.png` is the 512 px icon), the privacy policy, the content
   rating and the Data safety form.
4. **Add Play's app signing fingerprint** to
   `POLARIS_ANDROID_SHA256_FINGERPRINTS` on the app's server, beside the
   upload key's.
5. **Each release:** raise `appVersionCode` (and `appVersion`) in
   `twa-manifest.json`, then build. The project regenerates itself.

Bubblewrap can also upload builds itself (`bubblewrap play`) with a service
account. That is optional.
